# Socket bootstrap

The socket entry shares transport contracts with HTTP without conflating their security models. Keep browser-only helpers behind `/client`; the server barrel can import Node APIs. Socket handshakes must apply the origin policy and the configured session mode; do not treat a declared HTTP method as socket authorization. See `../src/client.ts`, `../src/extractToken.ts`, `../src/checkOrigin.ts`, `../../server/src/loadSocket.ts`.

Cookie-backed writes require CSRF tokens, while bearer-mode callers explicitly supply credentials. CSRF tokens cached in the browser are origin-scoped so an unrelated endpoint cannot inherit them. Offline queues are a delivery convenience, not permission to replay a request without server-side auth or validation. See `../src/csrf.ts`, `../src/offlineQueue.ts` and `../../server/docs/security-defaults.md`.

**Local socket maps are unreachable by default.** The adapter's room and socket-id maps and the server's socket list know only this process's sockets, so a helper built on them looks complete on one instance and silently misses the rest of the cluster on two — a failure that surfaces only in a split deployment, where it is hardest to attribute. Three layers keep consumer code off that path (ADR 0061): a lint rule catches what is written, a cross-instance room helper makes the right path the shortest, and outside production the registered server is handed out as a guarded view that throws on the same surfaces, catching computed access no static rule sees. Looking up one socket by id stays allowed. Production returns the raw server because a throw on a hot path is worse than a missed recipient. Deliberate per-instance work (cleaning up this process's own connections, sampling its backpressure) asks for the raw server explicitly and carries a lint opt-out with a reason, so a reviewer can find it. The room helper throws when no server is registered: an empty result would be indistinguishable from an empty room. Source: `../src/roomSockets.ts`, `../src/localSocketEnumerationGuard.ts`, `../src/eslint/rules/no-local-socket-enumeration.ts`.

**A room-name formatter receives `userId` as context, never as a name part.** Every framework join, leave, broadcast and presence room passes through the registered formatter, intended for a stable, user-independent transform such as per-tenant prefixing. For a broadcast the framework passes whoever performs the operation — the joiner on join, the sender on fan-out, the originator of a stream — so for a shared room the value differs per side. A formatter that folds it into a content room's physical name puts join and fan-out in different rooms, and every broadcast silently reaches nobody; the framework cannot detect this because both names are just strings. Put per-user isolation in the raw room code the consumer chooses, or in the presence family, which is per-user by design (ADR 0060). Source: `../src/roomNameFormatterRegistry.ts`.

# HTTP route ownership

The server coordinates framework auth, API/sync, health, uploads and consumer routes behind one origin and CSRF boundary. A custom route must not silently bypass those protections; an origin-exempt signed webhook must validate its own signature. A static/SPA fallback must not mask errors from state-changing routes. Source: `../src/httpHandler.ts`, `../src/httpRoutes/`, `../src/customRoutesRegistry.ts`.

Health and test routes have different trust models: health probes need to work without browser headers, while the test reset route must fail closed in production and without its token. The reset can be scoped to named targets so an authenticated test sweep can drain rate-limit buckets without deleting its own session; the unscoped reset keeps its original meaning (ADR 0064, details in `./security-defaults.md`). Streaming requires an HTTP response lifecycle distinct from ordinary JSON, but keeps the same auth gates. See `./security-defaults.md`, `../src/httpRoutes/healthRoutes.ts`, `../src/httpRoutes/testResetRoute.ts`, `../src/sse.ts`.

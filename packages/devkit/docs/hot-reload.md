# Hot reload design

Development route loading serves requests from in-memory registries. Regenerating the editor-facing type artifacts, and reading a reloaded route's input type, both build the TypeScript Program synchronously, so the dev server answers no request while that runs; deferring the work only lets the current event finish first. The pause is accepted for development rather than moving generation into a separate process, and its duration is logged so a stalled request has a visible cause. File-event bursts are coalesced, and a generation already in progress gets a follow-up pass instead of competing builds. Deferring heavy work lets the server listen before the TypeScript Program is built. Consult the watcher source for event classification and timing rather than maintaining a second event-flow implementation here.

A route file's own change reloads only that route in place. A change to a file a route imports is different: re-importing the route does not re-evaluate its imports, because the ESM loader caches them by URL and the cache-busting query reaches the route module only. Under the supervisor the dev server therefore asks for a restart; without it, the affected routes are re-imported so their input types refresh, and a warning says the handlers keep the old code until a restart. Files under a route marker that are not route surface (private `_`-prefixed helpers, test files) are dependencies, not misnamed routes. Generated outputs must not trigger their own watcher loops. Empty route files, or ones holding only the injector's own guidance line, can receive starter templates; any other content is the developer's, even when it arrives by rename or checkout, and is never overwritten. Paired sync files should remain type-consistent. Preserve the distinction between runtime reload and generated developer artifacts: a generation failure can leave IDE hints stale without justifying a production-path dependency on devkit.

Production does not start these watchers. If the live registry appears stale, inspect watcher errors and route naming before relying on regenerated files as proof the running handler was replaced.

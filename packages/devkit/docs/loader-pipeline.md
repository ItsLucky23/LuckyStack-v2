# Development loader

The loader mirrors production route resolution in development while allowing source changes to replace live handlers. Its exported maps retain stable object identity so consumers holding a reference see updates rather than abandoned snapshots. Route naming is validated before the initial load: failing early is safer than serving only part of a misnamed route tree. The production server instead uses generated maps; never bundle devkit as a runtime loader.

Dynamic imports avoid synchronous module evaluation on the Socket.io thread and must be fresh across reloads. A failed import should not replace a working handler with half-loaded state. Boot-time TypeScript Program initialization is intentionally shared across initializers; invalidate caches when sources change, not repeatedly during initial population. See `hot-reload.md` for the reason artifact generation is decoupled from serving requests and `ts-program-cache.md` for invalidation rationale. Source is authoritative for keys, regexes and function signatures.

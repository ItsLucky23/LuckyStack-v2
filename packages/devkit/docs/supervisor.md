# Development supervisor

A development supervisor restarts the child server when changes cannot safely be handled by live route reload alone. Keeping a small parent process separate from the running server allows a clean replacement without assuming that old module state is reusable. The watcher must coalesce rapid edits to avoid repeatedly starting partially-written code. See the supervisor source for exact state transitions, watched paths and timing.

The child can also ask for a restart over the IPC channel when a file a route imports changes, because in-process reload cannot refresh a route's imports (see `hot-reload.md`). At most one child runs at a time: a pending crash restart and a watcher restart must not each start one. Shutdown should release the child and watchers rather than leaving duplicate servers attached to the same port. This is development-only machinery; production orchestration belongs to the deployment platform. For route-only changes, prefer in-process hot reload to avoid unnecessary full-server restarts; see `hot-reload.md`.

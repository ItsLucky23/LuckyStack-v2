# Type-map generation

Generated route types, runtime schemas and API documentation must describe the same source route contract. TypeScript source is the authority; generated files are artifacts, not independent hand-maintained interfaces. Transport contracts must reject unsafe shapes rather than implying values can cross JSON or socket boundaries unchanged. A source missing from the compiler Program or an unresolved symbol deserves an explicit diagnostic, not a silent fallback that widens validation.

The emitter detects ambiguous route names before writing contradictory maps. Deep type expansion is bounded so pathological types cannot stall every generation. Development may report a loose schema when strict conversion is impossible, but its diagnostic must remain visible to the developer. Consult the emitter implementation for artifact names, current extraction rules, and schema policy. See `ts-program-cache.md` for the reason caches are reused and invalidated.

**An absent optional sync side is not a fallback.** The client handler of a sync route is optional by design (it runs once per recipient, so a pass-through one should not exist), and an absent side produces the same default text as a present side that declares no shape. Counting it as degraded extraction made the diagnostics gate push authors toward handlers the architecture forbids, so the generator records which sides exist and the diagnostics skip only the missing side's own field — after the thrown-extraction check, which always reports. Keep the exception that narrow: widening it per route, to API defaults, or ahead of the throw check would again make a lost shape indistinguishable from an undeclared one (ADR 0057). Source: `../src/typeMap/emitterArtifacts.ts`.

**Server-backed sync routes get the same metadata and input schemas as API routes.** Their auth and rate-limit settings are read with the same extractors as the API side, and their client input runs through the same schema converter and diagnostics, so the test-runner's contract and fuzz sweeps can reach sync routes the way they reach API routes (ADR 0064). A client-only sync is not a callable route and gets neither. Output and stream types never get a runtime schema. Source: `../src/typeMapGenerator.ts`, `../src/typeMap/emitterArtifacts.ts`.

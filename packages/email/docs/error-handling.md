# Email failures and observability

A normal provider failure should be observable without requiring every caller to catch an exception; callers still need to inspect the returned result and act on failure. When missing email breaks authentication or billing, require a configured real sender and fail loudly rather than silently reporting progress. The installed `EmailResult` type and sender source define current reasons; do not maintain a second list here.

A network failure can leave delivery **unknown**. Do not retry with a new idempotency key or assume the recipient did not receive the message. Suppress sensitive recipient addresses and provider error details from logs and tracker events. Recipient hashes sent to external trackers should use a secret HMAC key: an unkeyed hash of a common address can be guessed offline. Sanitize CR/LF in every message header, including custom and attachment headers, before handing data to an SMTP adapter so user-controlled input cannot inject extra headers. A dead-letter process must preserve the original logical delivery identity. An alert callback is not a delivery guarantee. A pre-send stop signal suppresses delivery, while thrown hook errors do not; mandatory consent checks must fail closed across all sending entry points. See [hook safety](./hooks.md).

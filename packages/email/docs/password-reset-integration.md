# Password-reset email integration

The framework-owned reset flow uses the email package so a project can choose or replace delivery without forking login. If you opt into the framework flow, install the mail package, register a real sender before requests begin, and set the public app URL correctly: otherwise reset links or delivery can fail. See `@luckystack/login` configuration and the email sender's types for current boot options.

**Do not disclose account existence.** A request for an unknown address should be indistinguishable to the client from one that can receive a reset email. Reset tokens must not be stored raw, logged or reused across attempts. Email delivery failure and retries must not weaken this property; do not tell the caller whether an address was found. A project with custom reset logic owns its own timing and enumeration defenses. The source and [framework email architecture](https://github.com/ItsLucky23/LuckyStack-v2/blob/main/docs/ARCHITECTURE_EMAIL.md) are authoritative for current templates and flow, not a copied walkthrough here.

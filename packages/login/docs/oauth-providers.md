# OAuth providers

Provider adapters keep protocol-specific account retrieval separate from application identity. A provider email is not automatically proof that two different provider accounts should be merged; select an account-linking strategy deliberately and enforce its database uniqueness assumptions. See `../src/oauthProviders.ts`, `../src/accountStrategy.ts`, `./user-adapter.md`.

A first sign-in creates an account only from an email the provider vouches for; otherwise anyone could squat a victim's address. GitHub's profile email carries no verified flag, so the address comes from GitHub's verified email list. Microsoft's `mail` is set by the tenant's administrator, so it is trusted only when the app is bound to one tenant: under `common`, `organizations` or `consumers` any tenant could assert any address, so new Microsoft users are refused there (existing ones still sign in). That closes sign-up, not takeover: an existing Microsoft account on a multi-tenant app is still matched by that unverified `mail`, so an admin of another tenant who sets it to a user's address signs in as that user. Blocking it would lock every existing multi-tenant user out, so the provider only warns at boot; the real fix is a single-tenant app, or binding accounts to the provider's subject id, which needs a schema change. Because OAuth accounts are found by email plus provider, their email belongs to the provider; the reference settings flow refuses to change it rather than orphaning the account or letting a stolen session rebind it.

Bind authorization callbacks with server-generated, single-use state and validate return URLs before redirecting the newly authenticated browser. The provider callback origin and public frontend origin can differ; do not turn a relative redirect into an attacker-controlled backend URL. Extra provider session data is visible to that user's browser; keep secrets out. Provider-supplied names are untrusted text and must be safely rendered wherever used. Source: `../src/login.ts`, `../src/redirectResolver.ts`, `../../server/src/httpRoutes/authCallbackRoute.ts`.
